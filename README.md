# Дашборд по домам — общая разметка

Одна страница по одному постоянному адресу. Открывают двое, размечают
оба, отметки и заметки видны обоим и сохраняются сами.

```
браузер  ──→  Cloudflare Pages   страница (public/index.html)
             ↕ /api/marks        функция синхронизации
             D1                  отметки, с журналом правок
```

Репозиторий держит **только развёртывание**. Генератор страницы,
выгрузки и данные остались в задаче (`Task - search house in
Kaliningrad`): переносить их сюда значило бы раздвоить библиотеку,
общую с квартирной задачей.

## Как это устроено

**Отметка привязана к id объявления** вида `domclick:https://…` —
источник плюс ссылка без параметров. Ключ детерминированный, поэтому
пересборка страницы с новыми объектами и другим оформлением накопленную
разметку не роняет.

**Правки уходят по полям, а не записями.** Человек ставит метку — на
сервер уезжает только цвет. Отсутствие поля в запросе значит «не
трогай», явный `null` — «стёрто». Если отправлять запись целиком, метка
увозит с собой устаревшую копию чужой заметки и молча её затирает.
Это уже случалось; проверка `check-sync.js` держит случай под контролем.

**Каждая правка попадает в журнал** (`marks_log`). Пока вход на страницу
не закрыт, ссылка равна праву записи — откатить порчу можно только по
журналу и по ежедневному снимку в `backup/`.

## Первая настройка

Node на этой машине портативный и в PATH его нет, поэтому `npx` не
работает. Все команды wrangler зовутся через обёртку `cf.cmd` из этой
папки — она подставляет нужный node сама.

```bat
cf login
cf d1 create dom-kgd-marks
```

Полученный `database_id` вписать в `wrangler.toml`, затем:

```bat
cf d1 execute dom-kgd-marks --remote --file=schema.sql
cf pages project create dom-kgd-2be42d1d18 --production-branch main
cf pages secret put SYNC_TOKEN
cf pages deploy
```

`SYNC_TOKEN` — содержимое `.sync-token` (файл не коммитится). Он же
вшивается в страницу при сборке, поэтому значения обязаны совпадать.

## Обычный цикл работы

```bat
rem из папки задачи: пересобрать страницу с данными
node tools\dashboard-houses.js --deploy

rem проверить перед выкладкой
node ..\tools\check-dashboard.js Rep\public\index.html
cd Rep && node tools\check-sync.js

git add -A && git commit -m "данные на 21 августа" && git push
```

Cloudflare Pages подхватывает push и обновляет страницу сам. Адрес не
меняется никогда — ссылку у отца менять не нужно.

**Сборка без `--deploy`** делает датированный `dashboard_<дата>.html`
в папке задачи: это архив, он работает без сервера и без токена, и
разметка в нём своя, местная.

## Перенос разметки из локального файла

```bat
node tools\import-marks.js dom-kaliningrad-otmetki.json --url https://<адрес>/api/marks
node tools\import-marks.js dom-kaliningrad-otmetki.json --url https://<адрес>/api/marks --apply
```

Первая команда — сухой прогон: сколько отметок легло на объекты и
сколько повисло. Повисшие (объявление сменило ссылку или ушло из выдачи)
выгружаются в `backup/orphans-<дата>.json` и при записи сохраняются
тоже — объявление может вернуться.

Принимаются оба носителя: `.json` от кнопки «Только отметки» и `.html`
от «Сохранить страницу с отметками».

## Проверки

| Команда | Что доказывает |
|---|---|
| `node ..\..\..\tools\lib\review-table.js` | обвязка таблицы и слой синхронизации, 63 проверки |
| `node ..\..\tools\check-dashboard.js Rep\public\index.html` | страница жива в браузере: фильтры, метки, заметки |
| `node tools\check-sync.js` | **два независимых браузера видят разметку друг друга** |
| `node tools\backup-marks.js --url …` | снимок разметки в `backup/` |

`check-sync.js` поднимает локальный сервер с локальной базой и ничего
не пишет в боевую разметку. Базу он пересоздаёт целиком: остатки
прошлого прогона делают стенд зелёным на сломанном коде.

## Что здесь намеренно неудобно

- **Правку по строке, в которой стоит курсор, человек увидит после того,
  как из неё уйдёт.** Опрос не трогает поле под курсором — иначе чужая
  метка затирала бы текст на полуслове.
- **Побеждает более поздняя правка.** Двое, правящие одну и ту же
  заметку одновременно, получат версию того, кто закончил вторым.
  Разные поля и разные объекты не конфликтуют вовсе.
- **Вход на страницу не закрыт.** Любой, кому попадёт ссылка, может
  править разметку. Защита — неугадываемый адрес, журнал и бэкап.
  Закрывается включением Cloudflare Access на две почты; страницу для
  этого менять не нужно, обработка истёкшей сессии в ней уже есть.
